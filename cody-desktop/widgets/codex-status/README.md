# Cody desktop companion

The desktop widget in this directory is based on the 0.4.2 OpenAI Usage source. Its compact toolbar retains the OpenAI quota display. Windows uses WinUI 3; Linux uses GTK 4/libadwaita and currently still uses the shared .NET account reader. Cody connection and PC monitoring use the existing Python companion service. A Python account reader for Linux remains future work.

The tray menu opens Cody Setup, About Cody, onboarding, and PC Alerts. The setup can discover and pair a physical Cody through an explicitly configured companion launcher. PC Alerts provides rule editing and monitor controls; available metrics depend on the running monitor. Rules send their selected information, warning or critical severity to firmware that authenticates the PC alert capability. Alerts remain queued rather than losing severity when capability is unconfirmed; the panel shows the observed capability and delivery errors. Queue admission is not device display confirmation. Device delivery and physical reactions require separate validation.

On Windows, Cody Setup can request Windows notification access and select a physical Cody and applications represented in current notifications. The widget forwards a generic event without the notification contents. The active listener is owned by the widget and remains active while it runs; the service response acknowledges admission, not display. Windows notification access requires an appropriate package identity and the userNotificationListener capability; an unpackaged or MSI installation may not provide it. The MSIX manifest declares the capability. Current CCP payloads are authenticated but readable on the local network, so generic notifications contain no application name or message text.

State, settings, history and logs for this copy are independent of the original OpenAI Usage app: Windows uses `%LOCALAPPDATA%/CodyCompanion`; Linux uses `$XDG_STATE_HOME/cody-companion` or `~/.local/state/cody-companion`. The original application and its data are not migrated. The Windows mutex, startup setting, MSIX identity, and MSI upgrade code and install directory are distinct. The Debian package, launcher and directories also have separate identities. Packaging and native execution remain unverified until explicitly authorized and run.

The target version is 0.4.2. Source-built installer names are `CodyCompanion-0.4.2-windows-x64.msi` and `cody-companion_0.4.2-1_amd64.deb`. The MSIX needs a signing certificate trusted on the installation machine. MSI and DEB packaging are not substitutes for checking the notification listener or native Linux behavior. Do not install from a prebuilt application copy.

Build and packaging scripts preserve generated outputs and dependency staging. Tests, scans, installation and device operations require separate authorization under the repository working agreements. Generated material can be cleaned up manually upon an explicit request.
